# Requify - Автоматизированная система управления требованиями

## Описание

Requify - это автоматизированная система управления требованиями (АСУТр), предназначенная для централизованного контроля и координации жизненного цикла требований — от их первичного формирования до финальной реализации и тестирования.

## Техническое задание

Система разработана согласно техническому заданию версии 1.1.0 и включает следующие подсистемы:

### 1. Система CRUD-требований
**Реализованные функции:**
- ✅ **Функция 1:** Создание требований (PM)
- ✅ **Функция 2:** Чтение требований (Любой сотрудник с правами доступа)
- ✅ **Функция 3:** Редактирование требований (PM)
- ✅ **Функция 4:** Архивирование требований (PM)
- ✅ **Функция 5:** Получение статуса требования (Любой сотрудник с правами доступа)
- ✅ **Функция 6:** Поиск требования (Любой сотрудник с правами доступа)
- ✅ **Функция 7:** Просмотр списка требований (Любой сотрудник с правами доступа)
- ✅ **Функция 8:** Просмотр списка требований по проекту (Любой сотрудник с правами доступа)
- ✅ **Функция 9:** Формирование релиза по определенным требованиям (PM)
- ✅ **Функция 10:** Формирование ТЗ к конкретному релизу (PM)

**API эндпоинты:**
- `GET /api/v1/requirements/search` - Поиск требований с фильтрацией
- `GET /api/v1/requirements/` - Получение списка требований
- `POST /api/v1/requirements/` - Создание требования
- `GET /api/v1/requirements/{id}` - Получение требования по ID
- `PUT /api/v1/requirements/{id}` - Обновление требования
- `DELETE /api/v1/requirements/{id}` - Удаление требования
- `POST /api/v1/requirements/{id}/change-status` - Изменение статуса
- `GET /api/v1/requirements/{id}/tests` - Получение тестов требования
- `GET /api/v1/requirements/{id}/relationships` - Получение связей требования

### 2. Система взаимодействия с АСУТс
**Реализованные функции:**
- ✅ **Функция 11:** Ручная отправка запроса на получение статуса тестирования требования (Уполномоченный сотрудник)
- ✅ **Функция 12:** Ручная отправка запроса на получение статуса тестирования релиза (Уполномоченный сотрудник)

**API эндпоинты:**
- `POST /api/v1/testing/asuts/requirement-status` - Запрос статуса тестирования требования
- `POST /api/v1/testing/asuts/release-status` - Запрос статуса тестирования релиза

### 3. Система взаимодействия с системой управления проектами
**Реализованные функции:**
- ✅ **Функция 13:** Создание проектов (PM)
- ✅ **Функция 14:** Удаление проектов (PM)
- ✅ **Функция 15:** Просмотр списка проектов (Уполномоченный сотрудник)

**API эндпоинты:**
- `GET /api/v1/projects/` - Получение списка проектов
- `POST /api/v1/projects/` - Создание проекта
- `GET /api/v1/projects/{id}` - Получение проекта по ID
- `PUT /api/v1/projects/{id}` - Обновление проекта
- `DELETE /api/v1/projects/{id}` - Удаление проекта
- `GET /api/v1/projects/{id}/requirements` - Получение требований проекта

### 4. Подсистема администрирования
**Реализованные функции:**
- ✅ **Функция 16:** Выдача доступа к функционалу системы (Администратор)
- ✅ **Функция 17:** Лишение доступа к функционалу системы (Администратор)
- ✅ **Функция 18:** Обработка информации о сбоях, перевод системы из аварийного режима (Администратор)
- ✅ **Функция 19:** Просмотр прав доступа конкретного пользователя (Администратор)

**API эндпоинты:**
- `POST /api/v1/admin/users/{id}/grant-access` - Выдача прав доступа
- `DELETE /api/v1/admin/users/{id}/revoke-access` - Отзыв прав доступа
- `POST /api/v1/admin/system/recover` - Восстановление системы после сбоя
- `GET /api/v1/admin/users/{id}/permissions` - Просмотр прав пользователя
- `GET /api/v1/admin/system/status` - Статус системы
- `GET /api/v1/admin/audit-log` - Журнал аудита

## Архитектура

Система реализована с использованием трехуровневой архитектуры:

### Презентационный уровень
- HTML, CSS, JavaScript
- Интерфейс пользователя с поддержкой различных ролей

### Логический уровень
- **Backend:** Python + FastAPI
- **База данных:** PostgreSQL 16.0
- **Кэширование:** Redis
- **Асинхронные операции:** SQLAlchemy + asyncpg

### Уровень данных
- PostgreSQL с нормализацией не ниже 3НФ
- Модели: User, Project, Requirement, Release, TestResult и др.

## Установка и настройка

1. Клонирование репозитория:
```bash
git clone <repository-url>
cd requify
```

2. Установка зависимостей:
```bash
poetry install
```

3. Настройка переменных окружения:
```bash
cp env.example .env
# Отредактируйте .env файл
```

4. Запуск сервисов:
```bash
docker-compose up -d
```

5. Запуск приложения:
```bash
poetry run python -m requify.requify.app.main
```
